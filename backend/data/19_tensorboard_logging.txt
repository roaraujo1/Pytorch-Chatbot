Visualizing Training with TensorBoard

TensorBoard is a visualization toolkit, originally built for TensorFlow, that PyTorch integrates with via torch.utils.tensorboard. It's commonly used to track training and validation metrics, visualize model architectures, and inspect data samples over the course of a training run.

Basic Setup

from torch.utils.tensorboard import SummaryWriter

writer = SummaryWriter(log_dir="runs/experiment_1")

Logging Scalars

The most common use case is logging scalar metrics like loss and accuracy at each training step or epoch, so their trends can be visualized over time.

for epoch in range(epochs):
    train_loss = train_one_epoch(model, optimizer, train_dataloader)
    val_loss, val_accuracy = validate(model, val_dataloader)

    writer.add_scalar("Loss/train", train_loss, epoch)
    writer.add_scalar("Loss/validation", val_loss, epoch)
    writer.add_scalar("Accuracy/validation", val_accuracy, epoch)

Logging Images

For vision tasks, it's often useful to periodically log a grid of sample images, either from the dataset or from model predictions, to visually sanity-check what the model is seeing.

from torchvision.utils import make_grid

images, labels = next(iter(train_dataloader))
grid = make_grid(images)
writer.add_image("sample_batch", grid, epoch)

Logging the Model Graph

TensorBoard can visualize the computational structure of a model, which can help catch architectural bugs.

sample_input = torch.randn(1, 3, 32, 32)
writer.add_graph(model, sample_input)

Logging Histograms

Weight and gradient histograms over time can reveal issues like vanishing gradients or dead ReLU units, where a large fraction of weights or activations get stuck at zero.

for name, param in model.named_parameters():
    writer.add_histogram(f"weights/{name}", param, epoch)
    if param.grad is not None:
        writer.add_histogram(f"gradients/{name}", param.grad, epoch)

Viewing the Dashboard

Once logs have been written, the TensorBoard dashboard is launched separately from the command line, pointing at the log directory:

tensorboard --logdir=runs

This starts a local web server, typically at http://localhost:6006, where scalars, images, histograms, and the model graph can all be explored interactively.

Closing the Writer

It's good practice to explicitly close the writer once logging is complete, which flushes any buffered events to disk.

writer.close()

Failing to call close() (or flush()) can occasionally result in the most recent logged values not appearing in the dashboard, particularly if the training script exits abruptly, since SummaryWriter buffers writes internally rather than writing to disk on every call.
